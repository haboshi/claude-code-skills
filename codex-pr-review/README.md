# codex-pr-review

`gh pr create` を検知して、ブランチ全差分の Codex レビューを **PR 検収の一点で一度だけ** 走らせる
PreToolUse フック。

## なぜ別プラグインなのか

レビュー実績評価（153 実行・76.3M トークン）の推奨1 は「全体レビューは PR の検収時を基本にし、
通常の commit/push は増分にする」。増分化は `~/.claude/skills/codex-bridge` 側で実装したが、
PR 時点の横断レビューを自動化するにはフックの配線が要る。

グローバルのユーザー設定ファイルは secret-leak-guard が読み書きとも拒否するため、そこには配線できない。
**プラグインは自前で `hooks/hooks.json` を宣言できる**ので、保護された設定に触れずに同じ配線ができる。

## 住み分け

| いつ | 対象 | 担当 |
|---|---|---|
| commit / push ごと | 前回レビュー済みからの増分 | codex-bridge |
| PR 作成時 | ブランチ全差分（横断的な観点） | 本プラグイン |

スクリプトは複製せず、codex-bridge の `codex-push-review.sh --full` を呼ぶだけ。

## データの送信

**このフックはブランチ全差分を外部モデル（Codex）へ送る。** 機密リポジトリでは必ず無効化すること。

```bash
# リポジトリ単位（推奨・コミットして共有できる）
echo 'CBR_PR_REVIEW=0' >> .claude/codex-review-limits

# セッション単位
export CODEX_PR_REVIEW=0
```

`0` / `false` / `no` / `off`、行末コメント、前後の空白を無効化として読む。
**有効と見なすのは `1` / `true` / `yes` / `on` のみ**で、それ以外の値はすべて無効扱いにする。
「無効にしたつもりで送っていた」を避けるため、迷ったら送らない側に倒している。

## 走らない条件

| 条件 | 理由 |
|---|---|
| draft PR | 検収の場面ではない |
| 同一 HEAD でレビュー済み | PR 作成のやり直しで二度消費しない |
| 前回が未完了・スキップ | 完了したときだけ「レビュー済み」にする。見ていない HEAD を検収に通さない |
| 無効化設定あり | 上記 |
| codex-bridge / Codex CLI 未導入 | 単体では何もしない |
| git リポジトリ外 | 差分の概念がない |

何があっても `exit 0`。PR 作成は止めない。

## 脅威モデルと許容している範囲

**守る対象**: 意図しないコード差分の外部送信と、「検証されていない変更が検証済みとして検収を通ること」。

**送信可否を決めるのは無効化設定だけ**。draft 判定は「検収前の PR に無駄なレビューを走らせない」
コスト最適化であり、送信の可否は決めない。だから draft を判定できなかったときはレビューを実行する。
ここを「判定できないから走らない」に倒すと、レビューが存在しないのに存在するように見える方が危ない。
無効化設定は stdin に依存せず、設定ファイルが読めないときは送らない側へ倒す。

**許容している前提**（これらは本プラグインの対策範囲外）:

- ローカルの `.claude/codex-review-limits` と環境変数は信頼する。これらを書き換えられる攻撃者は、
  既にリポジトリと同じ権限を持つ。
- Codex CLI とそのサブスク認証は信頼する。送信先の妥当性は codex-bridge と CLI 側の責任。
- `codex-push-review.sh` の出力文字列で完了を判定する。同スクリプトは常に `exit 0` で終わるため、
  終了コードでは完了と失敗を区別できない。見出しの形（`Codex Push Review (<範囲>)`）を契約とする。
- フックの停止・無効化（プラグイン自体の削除や `disableAllHooks`）は防がない。これは利用者の権限。
