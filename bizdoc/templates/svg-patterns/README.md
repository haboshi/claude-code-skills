# SVG 図解パターン集 — 共通予防則（全パターン必須）

1. 文字幅の見積り: CJK 1文字 = 1em、半角 = 0.5em。ボックス幅 = 想定ラベルの見積り幅 + 左右 0.5em。
   各パターンが定めるラベル文字数上限を超える場合は、ラベルを短くするか図を分割する
2. `viewBox` のみ指定し、`width` / `height` の px 直書きをしない（`figure svg { width:100% }` が効く）
3. ルート要素に `role="img"` と `<title>`（+ 必要なら `<desc>`）を必須とする
4. `font-family` は指定しない（本文の system font stack を継承させる）
5. 色は tokens.css の CSS 変数を参照する（`fill="var(--accent)"` 等）。アクセント1色の原則は SVG にも適用。
   **唯一の例外がセマンティック色 `var(--warn)` / `var(--warn-soft)`**（v0.9.0）で、超過・未達・停止・
   要対処など「他と危険度が違う」1要素にだけ使える。accent が「主役はどれか」を指すのに対し、warn は
   「ここは種類が違う」を指す — 兼ねさせると両方の合図が消える。ただし **1図につき warn は1要素まで**で、
   予防則15（強調は同時1点）は accent と warn を合算して数える（accent 強調と warn 強調を同じ図に
   置かない）。success / info に相当する色は用意しない（増やすと図が信号機になる）
6. `<svg>` の入れ子は禁止（hub の SVG 検証ゲートの抽出が入れ子に対応しないため）
7. XML として整形式であること（属性は必ず引用符・タグは必ず閉じる。& は &amp;）。
   hub.mjs add の xmllint 検証で不正 XML は reject される
8. 文字は 14px 相当以上（viewBox 座標系で調整）。低コントラストのグレー文字をラベルに使わない
9. **「14px 相当」は実表示サイズ基準で、式で判定する**: 図は `width:100%` で figure の内側いっぱいに
   拡大・縮小表示される。その実幅を **W** とし、判定は次の 1 式で行う。

   ```
   実表示サイズ = font-size × W ÷ viewBox幅          W = 918px
   ```

   **W = 918px は「広い画面で見たとき」の基準値**（tokens.css の `body { max-width: 64rem }` −
   本文 padding 2.2rem×2 − figure の padding 1.05rem×2 − 枠線）。tokens.css の器の幅を変えたら、
   この 1 箇所だけを直せば全パターンの判定が追随する。

   規範: **font-size は 14.5 以上**（主ラベル 15）。**viewBox 幅 780 以下なら基準幅で合格**
   （14.5 × 918 ÷ 780 ≈ 17.1px）。780 を超える図は上式で実表示を計算し、**14px 以上**を確認する
   （実例: 幅 1400 で font-size 15 のままだと 15 × 918 ÷ 1400 ≈ 9.8px で違反。22 以上に上げる）。

   **W は表示条件で変わる。この規範が保証するのは基準幅での可読性だけ**である:

   | 条件 | 実効 W | viewBox 780・font-size 14.5 の実表示 |
   |---|---|---|
   | 広い画面（ビューポート 1094px 以上） | 918px | 約 17.1px（本文 16px より大きい） |
   | 狭い画面（ビューポート 768px） | 約 662px | 約 12.3px |
   | A4 印刷 | 約 612px | 約 8.5pt 相当 |

   狭い画面と印刷では図全体が縮み、図中文字も一緒に小さくなる（レイアウトが等比で縮むため）。
   印刷の約 8.5pt は figcaption 8.5pt・表 9pt と同水準なので紙面としては整合する。
   **狭い画面での可読性を厳密に要求する文書では、viewBox 幅をさらに小さく（600 程度）取る**。

10. **図の高さは viewBox 500 以内を推奨**（A4 印刷でおよそ半ページ）。図は印刷時に途中で割らない設定のため、
    ページ残量より高い図は丸ごと次ページへ送られ、直前に余白が生まれる。半ページ以下なら大半の残量に収まり、
    この余白が構造的に出にくい。500 を超える情報量になったら図を2枚に分割する

11. **無名の箱を描かない**: 図中の主要ボックスには「名詞＋数値」の副ラベルを付ける（「要約系 4回」「候補 3件」）。
    数値を持たない要素は、統合するか、そもそも描く必要があるか見直す。副ラベル追加で viewBox 幅が
    予防則9 の上限を超えるなら図を分割する（1図1主張は不変 — 密度は1つの主張を支えるラベル・数値の
    密度であり、主張の数ではない）

12. **読み順と終端**: 流れ系パターン（process-flow・手順・状態遷移）は読み順を丸数字①②③…で明示する。
    流れの終端には ✓（到達・解決）か ✗（未達・問題）を置き、宙に浮く矢印を残さない

13. **実データ標本**: 設定値・パス・環境変数・係数は抽象記号に置き換えず、実物の文字列を
    `font-family` 無指定の monospace 風（`<tspan>` で `letter-spacing` を締める程度）で一字一句正確に描く。
    強調は該当部分文字列だけをアクセント色の点線枠で囲む（読者が図を信じる根拠を図の中で渡す）

14. **反復は個数で見せる**: 「N回・N件」が主張そのものなら、同一図形を実際に N 個並べる（数量の反復描画が
    証拠になる）。N が 9 を超えるときは代表数個＋「×N」表記に切り替える（要素数と幅の制約が勝つ）

15. **強調は同時1点**: accent 色・矢印・点線枠による強調は1図あたり同時1点まで（3点以上光らせると合図が
    消える — 強調は稀少資源）。複数箇所を強調したい図は分割するか、番号順路（予防則12）で時間差をつける

drawio（Mermaid 経由）への適用: ノードラベルに副ラベルを併記（`A["要約系<br/>4回"]`）、edge label で
判定を書く（`-->|✓ 到達|`）、読み順は番号をラベルに埋める。

HTML 側との接続: 図中ラベルの語彙 = 本文の主語群（言い換え禁止）。figcaption は図の主張1文の
ナレーション。これにより「図を読む → 同じ語で本文が歩く」の往復ゼロ導線が成立する。
下段テイクアウェイ帯・決め数値バッジはラスタ（B2 spec）専用 — SVG では figcaption と文書側の
kpi-grid / callout がその役割を担う（帯を図内に持つと1図1主張と幅制約に衝突する）。

## 様式イディオム（v0.2 で確立。新しい図もこの様式に揃える）

- **ノードは2行構成**: 主ラベル（font-size 15・`var(--ink)`）+ 副ラベル（14.5・`var(--ink-2)`）。1行だけの箱を並べない（情報密度が落ちる）
- **注釈行**: 図の下部に「7×7 の `var(--accent)` 正方形 + 注釈文（14.5・`var(--ink-2)`）」を 0〜2 行。図の含意・運用上の約束をここで言い切る
- **白は `var(--bg)`**: ノード背景等に `#ffffff` を直書きしない（テーマ変数の一貫性）
- **枠のグルーピング**: 関連要素は薄い面（`var(--bg-soft)` + `var(--line-strong)`）か破線枠で束ねる。破線 = 「将来・自動・付随」の意味で使う
- **強調は1箇所**: `fill="var(--accent)"` + 白文字はページの図全体で最も重要な1要素だけ

## 埋め込み時の注意（予防則の補足）

- これらの SVG は文書 HTML に**インラインで貼る**こと。`<img src="pattern.svg">` のように外部ファイル参照にすると、
  SVG 内の `var(--accent)` 等が文書側 `:root` の CSS 変数を解決できず、無色・黒塗りになる。
- 各パターンの `marker id`（矢印定義など）は同一文書内で他パターンと衝突しないよう、パターンごとに
  異なる id を使う（例: process-flow は `ar`、architecture は `ar-arch`）。同一文書に複数の図を貼るときは
  衝突がないか目視で確認する。
