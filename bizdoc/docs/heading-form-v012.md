# bizdoc v0.12「役割ラベル — 主張句」見出し 設計メモ

対象: bizdoc 0.11.3 → **0.12.0**（2026-09-08）。変更は見出し層（`h2`・`.sec-lede`・目次・番号の見た目）だけで、本文・図・表の規範は動かしていない。

## 1. きっかけ

オーナー所見（2026-09-08）: 「bizdoc の各セクションのタイトルが読みにくく、唐突で、認知負荷がある。run-explainer-page の出力の方がマシ」。

比較対象の explainer は全節が「役割ラベル（出発点／施策①／品質担保…）— 緊張を残す句」＋副題 1 行の一貫した二層。0.11.3 の bizdoc は単層の完全述語文 h2（最長 35 字・2 節）で、直下の `.sec-lede` も文なので「文＋文」が連続し、さらに v0.9.0 の「同一構文 3 連続で別型へ」により 1 文書に断定・疑問・機能ラベルが混在していた（当日の runbook 実測: 機能ラベル 1・断定 4・疑問 2）。

v0.7 設計文書の storyDiff は「A の見出しは役割ラベル — 緊張を残す主張」と記録していたが、v0.8 のレジスター規範（1 見出し 1 主張・ダッシュ後は補強のみ・用言で言い切る）へ落とす過程で役割ラベル層が消えていた。v0.8 のブラインド審査 3/3 勝利は「タイトル数値一致・B2 図の自立性」が勝因で、見出し形式は独立変数として分離されていない。

## 2. 体感 A/B（同一文書・見出し層だけ差し替え）

過去文書 2 本（0.11.3 出力の手順書 8 節、旧版出力の報告書 9 節）に対し、本文・図・表を固定して見出し層だけを差し替えた 3 版を横並びで比較した（ローカル doc-hub の `_experiments/heading-ab-20260908/`。顧客情報を含むためリポジトリには置かない。生成スクリプト `revise_headings.py` を同梱）。

| 版 | h2 | `.sec-lede` |
|---|---|---|
| 原本 | 主張文のみ（3 型混在） | 意外な一点 |
| 案A 二段 | 役割ラベル — 20 字以内の句（体言止め） | 主張文（旧 h2）を太字で |
| 案B 複合 | 役割ラベル — 用言を含む主張句 | 意外な一点（原本のまま） |

結果: **案B が「明らかに頭に入る」**（オーナー体感、n=1）。

なぜ B か。役割ラベルが「どの種類の節か」を、主張句が「何を言うか」を同じ行で渡すので 1 チャンクで届く。案A は h2 と lede の 2 行を読んで合成しないと節の意味が確定せず、h2 の体言止めの断片は命題にならない（X の日本語圏で「動詞を落とした見出しは意味が取れない」と一致）。しかも lede が旧 h2 の言い換えになり「一度だけ言う」を破っていた。原本は種類の手がかりが無く、節ごとに見出し形式が変わる。コンサル資料の「タイトル＋メッセージライン」二段はスライドの枠内では効くが、スクロール文書では h2 が単独で自立している必要がある。

## 3. 変更点

- **SKILL.md §6**: 「見出しは『役割ラベル — 主張句』の二部構成」を柱に据え、v0.9.0 の「構文を散らす」「疑問形の許可枠」「機能ラベルの条件付き許可」を廃止。疑問は答えの形で書く。役割語彙の例（現状／前提／手順／本番操作／完了判定／裏取り／設計判断／提案／代替案／落とし穴／残リスク／効果／判断依頼／切戻し／付録）。長さは役割 5 字・主張句 20 字・全体 35 字。
- **SKILL.md §6**: `.sec-lede` は全角 60 字以内（器幅 954px・15px で約 63 字。1 行）。
- **SKILL.md §8**: 目次項目は「役割ラベル — 短縮した主張句」（役割ラベルは省略しない）。
- **SKILL.md §9**: 骨格検査を h2 列だけで行う。「構文検査」を「形式検査」（1 形式に統一されているか・役割語が中身と合うか）に置換。lede の 1 行検査を追加。
- **tokens.css**: 番号を太いアクセント色の数字＋h2 左バーに（小さな枠付きチップを廃止）。`.sec-lede` を `--measure` の対象から外し h2 と同じ幅で組む（実指摘: 44 字の lede が「〜確認と／記録であること。」で折れていた）。
- **版数**: plugin.json / marketplace.json ×2 を 0.12.0。

保存済み文書には tokens.css の変更は自動で届かない（注入時の CSS が焼き込まれる）。必要な文書は `hub.mjs retheme` で貼り直す。

## 4. 調査（Grok・X と Web）

`docs/research/heading-form-grok.md` に生出力を残した（X 投稿 37 件・Web 20 件、2025-09〜2026-09）。X 投稿のうち 4 件を syndication API で実在確認した（@masato_ka 2026-09-05／@shin_yoshimura0 2026-09-07／@rsensui 2026-08-26 は本文一致。@fujikururi 2026-08-07 は本文が画像のため要旨は未確認）。

要点: 実務の一致は「上段＝短いトピック／役割、直下＝主張文」の二段だが、これはスライド前提の観察であり、本件の体感ではスクロール文書で二段（案A）が負けた。完全な主張文型は有効だが原典（Alley）が「2 行以内」を条件にしている。疑問形見出しは AI 検索の引用率には有利でも、専門読者の読解負荷では否定的（Dunleavy、@masato_ka）。唐突さの要因として文献が挙げるのは「長い一文／節の種類が不明／前節との接続不明／番号・役割の手がかり無し」の 4 つで、対策は役割語の先置き・番号＋役割・目次と現在地。
